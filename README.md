## 📌 Executive Overview

Traditional venture capital in both tech and crypto markets suffers from massive friction:
- **Founders** spend 200+ hours sending hundreds of cold emails and telegram DMs into dead inboxes with zero feedback or accountability.
- **Investors** drown in noisy, unformatted pitches, phantom traction claims ("ghost rounds"), and unverified claims.
- **Service Providers & Agencies** struggle with client payment defaults, ambiguous milestone scopes, and lack of pre-funded escrow protection.

**Raisequity** solves this through a high-frequency, institutional deal intermediary platform powered by autonomous intelligence:
1. **Guaranteed 30-Day Partner Meeting SLA**: Founders receive 3 confirmed, stage- and check-size matched VC meetings within 30 days or a 100% automated refund.
2. **Double-Blind Dealflow Matching**: Founders and allocators evaluate cryptographically masked memos; contact details unlock only upon mutual opt-in.
3. **Institutional Dealflow Split-Pane Cockpit**: Allocators screen vetted startups in seconds with deep code traction diagnoses, GitHub commit audits, and ghost-round authenticity scoring.
4. **Milestone Escrow Vaults**: Agency and RFP engagements are secured on-chain and through smart milestone escrows, protecting both deliverable quality and payout certainty.

## 🚀 Quick Start

### Prerequisites
- **Node.js**: v18.0.0 or higher
- **npm** or **pnpm**
- **Git**

### Installation

1. **Clone the Repository:**
   ```bash
   git clone https://github.com/Akash1070/Raisequity.git
   cd Raisequity
   ```

2. **Install Dependencies:**
   ```bash
   npm install
   ```

3. **Configure Environment Variables:**
   Copy the example environment configuration:
   ```bash
   cp .env.example .env
   ```
   Fill in your Firebase credentials in `.env`:
   ```ini
   VITE_FIREBASE_API_KEY=your_firebase_api_key
   VITE_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
   VITE_FIREBASE_PROJECT_ID=your_project_id
   VITE_FIREBASE_STORAGE_BUCKET=your_project.appspot.com
   VITE_FIREBASE_MESSAGING_SENDER_ID=your_messaging_sender_id
   VITE_FIREBASE_APP_ID=your_firebase_app_id
   VITE_FIREBASE_MEASUREMENT_ID=your_measurement_id
   ```

4. **Start Development Server:**
   ```bash
   npm run dev
   ```
   The application will be live at `http://localhost:3005`.

## 🔒 Security & Database Rules

All client read/write interactions are guarded by institutional-grade Firestore security rules defined in [`firestore.rules`](./firestore.rules):
- **Role Isolation**: Strict boundaries preventing unauthorized cross-access between founders, investors, agencies, and platform administrators.
- **Double-Blind Anonymity**: Investor contact credentials and founder cap tables remain concealed until reciprocal authorization is registered.
- **Escrow Immutability**: Milestone release requests require co-signatures from both contracting parties before funds are disbursed.

## 🔏 E-Sign Workflow (OpenSign optional)

- **If `OPENSIGN_API_KEY` is configured**: `/api/opensign-agreement` generates the document via OpenSign; both parties sign on OpenSign; the app records the document ref.
- **If not configured (current default)**: the app uses the **Raisequity in-app sealed agreement flow** (`src/lib/sealedAgreement.ts`):
  1. Investor submits SAFE terms via the 1-Click SAFE modal.
  2. System builds the canonical agreement text, records the investor's typed-name consent + timestamp.
  3. Founder is notified (in-app + email) and reviews the full terms in Messages (`SealedSafeInbox`).
  4. Founder signs or declines; on signature the document is **sealed with a SHA-256 digest** and emailed to both parties.
- Payment expectations: the in-app flow records the investor's capital commitment (portfolio + safes) pending signature completion; it is an auditable consent record, not a licensed certification service.

## 🔒 Security Notes for Open-Source Repo

- The Firebase web API key is public by design but **must be referrer-restricted** (see checklist item 2).
- Admin access is protected by `VITE_ADMIN_EMAIL` + Firestore role; change the admin email env to a private address.
- All server keys (`DODO_*`, `RESEND_*`, `GEMINI_*`, `OPENSIGN_*`, `FIREBASE_SERVICE_ACCOUNT_JSON`) live only in Vercel env — never in the repo.
